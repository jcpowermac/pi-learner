# pi-learner

Trace-driven self-improvement extension for the [Pi coding agent](https://github.com/earendil-works/pi-coding-agent).

Mines runtime execution traces generated by [`pi-otel`](https://github.com/jcpowermac/pi-otel) (`.pi/traces.jsonl`) to detect recurring tool failures, prevent thrashing loops, and distill verified winning trajectories into actionable project guidelines.

## Features

- **3-Tier Zero-Bloat Knowledge Architecture**:
  - **Tier 1 (Code Sanitizer - 0 tokens)**: Auto-corrects mechanical tool arguments (e.g. leading `./` in file paths, trailing slashes) in `tool_call` before execution.
  - **Tier 2 (Capped Playbook - ~300 tokens fixed)**: Maintains a hard 30-line ceiling in `.pi/AGENTS.md` with LRU (least-recently-used) eviction for local models (Qwen 27B, etc.), preventing context window bloat.
  - **Tier 3 (JIT Deep Playbooks - 0 tokens until hit)**: Stores complex recovery playbooks in `.pi/playbooks.json` and injects transient 2-line recovery tips only when specific matching tool errors occur.
- **Rule of Three Gate**: Only promotes patterns verified across $\ge 3$ distinct sessions to filter out one-off noise.
- **In-Flight Circuit Breaker**: Stops tool retry loops if identical arguments fail twice consecutively in an active session.

## Installation

```bash
# Install globally in Pi settings
pi install ~/Development/pi-learner

# Or test ad-hoc in a single session
pi -e ~/Development/pi-learner
```

## Commands

- `/learn`: Manually trigger trace ingestion and guideline updates.

## Configuration

Configure via environment variables:

| Variable | Default | Description |
| :--- | :--- | :--- |
| `PI_LEARNER_DISABLED` | `false` | Set to `true` or `1` to disable all learner hooks |
| `PI_LEARNER_AUTO` | `true` | Automatically run learning pass on `session_shutdown` |
| `PI_LEARNER_MAX_AGENTS_MD_LINES` | `30` | Maximum lines for `.pi/AGENTS.md` block (~300 tokens) |
| `PI_LEARNER_RULE_OF_N` | `3` | Minimum sessions required before promoting a pattern |
| `PI_LEARNER_CIRCUIT_BREAKER_LIMIT` | `2` | Consecutive identical failures before tripping guard |
| `PI_LEARNER_TRACES_PATH` | `.pi/traces.jsonl` | Path to `pi-otel` trace log |
| `PI_LEARNER_AGENTS_MD_PATH` | `.pi/AGENTS.md` | Path to repository guidelines file |
| `PI_LEARNER_PLAYBOOKS_PATH` | `.pi/playbooks.json` | Path to Tier 3 playbook database (alias: `PI_LEARNER_DB_PATH`) |

## How It Works

```text
                  ┌─────────────────────────────────────┐
                  │          pi-otel Traces             │
                  │   (.pi/traces.jsonl - span history)  │
                  └──────────────────┬──────────────────┘
                                     │  /learn or session_shutdown
                                     ▼
                  ┌─────────────────────────────────────┐
                  │       pi-learner Pattern Miner      │
                  │       (Rule-of-Three Classifier)    │
                  └──────┬───────────┼───────────┬──────┘
                         │           │           │
           Mechanical    │    Core   │      Deep │ Esoteric /
           Parameter Fix │  Workflow │   Playbook│ Rare Errors
                         ▼           ▼           ▼
                   ┌──────────┐ ┌──────────┐ ┌──────────────┐
                   │  Tier 1  │ │  Tier 2  │ │    Tier 3    │
                   │ Code-Lvl │ │ Capped   │ │ SQLite / DB  │
                   │ Sanitizer│ │ AGENTS.md│ │ JIT Inject   │
                   └────┬─────┘ └────┬─────┘ └──────┬───────┘
                        │            │              │
      Context Cost:  0 tokens    ~300 tokens     0 tokens
                                   (fixed)      (until hit)
```

1. **In-Flight**: `tool_call` runs Tier 1 sanitization and checks the Circuit Breaker. If a tool fails, `tool_result` queries Tier 3 to queue a transient recovery tip for the next turn.
2. **Post-Session / `/learn`**: Scans the tail of `.pi/traces.jsonl`, extracts error-to-success pairs, groups by session, and updates `.pi/AGENTS.md` (capped at 30 lines) and `.pi/playbooks.json`.
