# Pi Trace-Driven Self-Improvement Extension (`pi-learner`) Design Specification

**Date:** 2026-09-04  
**Status:** Approved  
**Repository:** `~/Development/pi-learner`

---

## 1. Overview & Goals

`pi-learner` is a trace-driven self-improvement extension for the [Pi coding agent](https://github.com/earendil-works/pi-coding-agent). It consumes runtime execution traces generated by [`pi-otel`](https://github.com/jcpowermac/pi-otel) (`.pi/traces.jsonl`) to automatically detect recurring tool failure patterns, prevent thrashing loops, and distill verified winning trajectories into actionable project guidelines.

### Primary Goals
1. **Zero Context Explosion**: Prevent system prompt and context bloat by employing a strictly bounded, 3-tier knowledge architecture.
2. **Tier 1 (Deterministic Sanitizer - 0 tokens)**: Intercept and auto-correct purely mechanical tool parameters in `tool_call` without burning prompt tokens.
3. **Tier 2 (Capped Project Playbook - ~300 tokens fixed)**: Aggregate core repository workflow lessons into a single, compact `.pi/AGENTS.md` file with a hard 30-line ceiling and LRU eviction.
4. **Tier 3 (Deep Knowledge Store - 0 tokens until triggered)**: Store complex, esoteric error playbooks in a lightweight local database (`.pi/playbooks.db`) and inject transient 2-line recovery tips only when matching errors occur.
5. **In-Flight Circuit Breaker**: Prevent immediate thrashing loops in active sessions by detecting consecutive failures of the same tool or pattern.
6. **"Rule of Three" Promotion Gate**: Only promote patterns observed across $\ge 3$ distinct sessions to filter out single-session noise.

### Non-Goals
- **Replacing Developer Guidance**: Does not overwrite human-authored guidelines in `AGENTS.md`; appends/manages a designated `<!-- pi-learner:start -->` section.
- **Heavy Background Daemons**: Runs entirely in-process within Pi's extension lifecycle; no background servers or external vector databases required.

## 2. 3-Tier Architecture & Data Flow

```text
                  ┌─────────────────────────────────────┐
                  │          pi-otel Traces             │
                  │   (.pi/traces.jsonl - span history)  │
                  └──────────────────┬──────────────────┘
                                     │  /learn or session_shutdown
                                     ▼
                  ┌─────────────────────────────────────┐
                  │       pi-learner Pattern Miner      │
                  │       (Rule-of-Three Classifier)    │
                  └──────┬───────────┼───────────┬──────┘
                         │           │           │
           Mechanical    │    Core   │      Deep │ Esoteric /
           Parameter Fix │  Workflow │   Playbook│ Rare Errors
                         ▼           ▼           ▼
                   ┌──────────┐ ┌──────────┐ ┌──────────────┐
                   │  Tier 1  │ │  Tier 2  │ │    Tier 3    │
                   │ Code-Lvl │ │ Capped   │ │ SQLite / DB  │
                   │ Sanitizer│ │ AGENTS.md│ │ JIT Inject   │
                   └────┬─────┘ └────┬─────┘ └──────┬───────┘
                        │            │              │
      Context Cost:  0 tokens    ~300 tokens     0 tokens
                                   (fixed)      (until hit)
```

### In-Flight Runtime Flow (Active Turns)
1. **Prompt received**: Turn starts.
2. **`tool_call` hook fires**:
   - Tier 1 Sanitizer inspects tool arguments and auto-corrects known mechanical issues (e.g. normalizing relative paths, trimming stray quotes).
   - In-flight Circuit Breaker checks consecutive failure count for the tool/signature. If failing $\ge 2$ times, warns or aborts early with a pivot recommendation.
3. **Tool executes & `tool_result` hook fires**:
   - If `tool.is_error === true`: Tier 3 Playbook Reader queries `.pi/playbooks.db` in-process. If a matching past fix exists, queues a transient tip for the next turn:
     `"💡 Learner tip: Previous failure resolved by running: <command>"`

### Learning Analysis Flow (`/learn` command or `session_shutdown`)
1. **Trace Ingestion**: Parses spans from `.pi/traces.jsonl`.
2. **Trajectory Pairing**: Matches each error span (`tool.is_error: true`) with the subsequent successful tool span that resolved the task.
3. **Rule-of-Three Gate**: Clusters recurring failure-recovery patterns. Only patterns observed across $\ge 3$ distinct sessions qualify for promotion.
4. **Tier Routing & Compaction**:
   - Mechanical argument patterns are saved to Tier 1 sanitizer configuration.
   - Core workflow patterns are compiled into 1-line imperative bullets in `.pi/AGENTS.md` (bounded to 30 lines maximum).
   - Detailed troubleshooting recovery steps are stored in Tier 3 database (`.pi/playbooks.db`).

## 4. Lifecycle Hook Mappings

| Pi Event / Command | Trigger / Meaning | `pi-learner` Action |
| :--- | :--- | :--- |
| `tool_call` | Tool call initiated | Sanitizes parameters (Tier 1) and checks Circuit Breaker limit |
| `tool_result` | Tool execution finished | Records success/failure for circuit breaker; queries Tier 3 DB on error |
| `before_agent_start` | Turn about to start | Injects queued transient recovery tips from Tier 3 |
| `/learn` command | User command `/learn` | Manually triggers trace ingestion, rule-of-three mining, and updates `.pi/AGENTS.md` |
| `session_shutdown` | Session exits | Automatically triggers trace ingestion and learning pass (if `PI_LEARNER_AUTO=true`) |

---

## 5. Containment Rules & Compaction

1. **Hard 30-Line Budget in `.pi/AGENTS.md`**:
   - The learner manages a delimited block:
     ```markdown
     <!-- pi-learner:start -->
     - Run `podman build --platform linux/arm64` for multi-arch builds.
     - Use `npm test -- --runInBand` to prevent Jest worker port collisions.
     <!-- pi-learner:end -->
     ```
   - Content between the markers is strictly capped at **30 lines** (~300 tokens).
   - If a new rule would exceed 30 lines, the least-recently-seen rule (by trace timestamp) is pruned.
2. **Zero Ambient Tokens in Tier 3**:
   - Deep playbooks live in `.pi/playbooks.db`.
   - Never injected into system prompt.
   - Injected only as a 2-line user-turn message when the specific error signature is detected.

## 6. Configuration & Environment Variables

| Variable | Default | Description |
| :--- | :--- | :--- |
| `PI_LEARNER_DISABLED` | `false` | When `true`, disables all learner hooks |
| `PI_LEARNER_AUTO` | `true` | Automatically run learning pass on `session_shutdown` |
| `PI_LEARNER_MAX_AGENTS_MD_LINES` | `30` | Maximum lines allowed in `.pi/AGENTS.md` section |
| `PI_LEARNER_RULE_OF_N` | `3` | Minimum session count required for pattern promotion |
| `PI_LEARNER_CIRCUIT_BREAKER_LIMIT` | `2` | Consecutive identical failures before tripping guard |
| `PI_LEARNER_DB_PATH` | `.pi/playbooks.db` | File path for Tier 3 playbook database |

---

## 7. Error Handling & Non-Interference

1. **Defensive Isolation**: Every hook handler is wrapped in `try/catch`. Failures in trace reading, SQLite queries, or file writes are logged to console and never crash the active session.
2. **Atomic Writes**: `.pi/AGENTS.md` and `.pi/playbooks.db` are written using temporary file swap patterns (`.tmp` -> `renameSync`) to prevent corruption during unexpected shutdowns.
3. **Bounded Trace Reading**: `trace-reader.ts` reads at most the trailing 5MB / 10,000 lines of `.pi/traces.jsonl` to ensure low memory consumption.

## 8. Verification & Testing

1. **Unit Testing**:
   - Test bounded trace ingestion and JSONL parsing.
   - Test "Rule of Three" grouping: ensure patterns seen in 1 or 2 sessions are ignored, and patterns in $\ge 3$ sessions are promoted.
   - Test `.pi/AGENTS.md` 30-line ceiling and LRU eviction.
   - Test circuit breaker tripping on consecutive failures.
2. **Integration Testing**:
   - Simulate a full Pi turn sequence with synthetic errors and verify recovery tip injection.
   - Run `/learn` command against sample trace fixtures and verify generated `.pi/AGENTS.md` output.
